# 架构与扩展约定

目标是单节点、长期运行的 NAS 服务。管理 API 和代理监听分离；React 静态文件由同一个 Rust 进程提供。SQLite 是持久化的配置与状态源，内存保存代理路由快照、TLS 密钥对象、正在执行的任务及有上限的观测队列。访问观测使用独立的限容 SQLite，不与配置写入竞争事务。

## 依赖选择

| 领域 | 组件 | 项目负责的部分 |
| --- | --- | --- |
| 服务与异步 | Axum / Tokio | API 权限、参数合同、任务生命周期 |
| HTTP 与 WebSocket | Hyper / hyper-util | 域名路由、上游选择、转发头政策 |
| HTTP/3 | h3 / h3-quinn / Quinn | 有界 UDP 连接、流控、桥接既有代理 |
| 动态模板 | MiniJinja | 编译时表达式政策、只读请求上下文、执行与输出上限 |
| TLS | rustls / rustls-pemfile | SNI 映射、证书有效性、热加载 |
| 数据库 | SQLx / SQLite WAL | 版本化迁移、资源版本、事务恢复 |
| 密码与凭据 | Argon2id / AES-GCM | 一次性初始化、会话撤销、密钥保存 |
| ACME | 固定 lego 4.35.2 二进制 | 子进程隔离、环境凭据、续期计划、原子激活 |
| 前端 | React / TanStack Query / Zod | 查询生命周期、API 边界校验、交互与布局 |
| UI | Tailwind / 官方 shadcn + Radix | 主题、业务组件、可访问标签 |

lego 5.x 已改变 CLI 合同，不能仅修改镜像版本号升级。升级须同步编排实现并通过真实二进制参数检查、任务测试与签发验证。

## 模块

- `auth.rs`：密码、初始化令牌、cookie 会话、登录限流与 CSRF。会话随机令牌只在 cookie 中，数据库保存 SHA-256；12 小时固定有效期，修改密码撤销全部旧会话。认证写操作独立串行，防止并发中的旧密码登录在撤销后创建新会话；前端收到 401 会退出缓存页面并回到登录。
- `models.rs`：资源合同与输入约束。资源 ID 由服务端生成，域名和目标 URL 显式验证，禁止在目标 URL 内嵌登录凭据。
- `resources.rs`：CRUD、版本冲突、依赖删除保护。写入与后台任务入队共用操作锁；PUT 必须携带读取时的 `revision`，过期版本返回 409。
- `groups/`：分组名称、顺序与服务归属的版本校验；排序和批量归组使用配置库事务，只更新分组元数据，不刷新代理。`scope.rs` 负责观测查询中的当前成员范围；`backup.rs` 校验与重映射备份分组。
- `store.rs` / `migrations/`：持久化、密钥加密及数据库迁移。密钥在数据目录内，权限 0600，目录 0700。凭据查询永不返回密文或明文。
- `dns/`：每个供应商独立适配器；`provider.rs` 集中定义凭据与 ACME 环境映射。新增服务商在这里注册、增加契约测试并更新 UI 合同。
- `jobs.rs`：去重、四个并发执行槽、持久化运行状态与定时调度。失败保持可检查状态，下次周期重试；进程重启会恢复中断任务的可调度状态。每次执行查询服务商当前记录，避免只依赖缓存造成漂移。
- `certificates.rs`：ACME 与 PEM 导入。只把凭据放入子进程环境，不拼接 shell。发布前验证 SAN、有效期与私钥匹配，新证书写入新目录后原子切换 `live` 符号链接。
- `listeners.rs`：按入口隔离 SNI 证书及域名路由；附加入口由 `OPENLUCKY_LISTENERS` JSON 配置，IPv6 入口只接收 IPv6。可选同端口 HTTP/TLS 使用 Tokio peek 与 axum-server/rustls，不消费探测字节；探测和握手各限时 10 秒。
- `telemetry/`：访问日志、独立小时聚合、有界队列、容量与时间清理、受保护的分页查询、进程和容器资源采样。独立数据库及迁移位于 `telemetry.sqlite` 和 `telemetry_migrations/`，不把高频代理错误写入配置事件表。具体口径、脱敏和丢失边界见 [访问与性能观测](observability.md)。
- `web_options.rs` / `header_rules.rs` / `template_policy.rs`：Web 合同、预编译请求头操作与动态模板。MiniJinja 固定版本以校验其 AST；模板只允许有界字段、条件及过滤器，不提供文件、网络、任意函数、循环和算术扩展。固定头不进入模板执行路径。
- `gateway_limits.rs` / `http3.rs`：校验启动容量参数并桥接 UDP/TLS 1.3 与 HTTP/3。NAS 默认全进程最多 64 个 QUIC 连接和 256 个请求，每连接 32 个请求流、1 MiB 接收窗口、2 MiB 发送窗口，每流 1 MiB 接收窗口和 2 帧通道。连接数乘以收发窗口之和不得超过窗口预算（默认 192 MiB）；该预算不包含协议元数据、其他协议和连接池。关闭 0-RTT，首次握手要求地址验证；退出时关闭端点和关联任务。
- `proxy.rs`：以哈希表查找共享路由快照，配置刷新时预解析 URL、编译头与 TLS 配置；按上游版本/连接超时复用连接池，每目标默认最多 256 条空闲连接（启动参数可调）、60 秒空闲回收。只转发已启用的域名。原始字节流和 WebSocket 使用 Hyper 原生实现；HTTPS 上游使用可信根校验。清除用户提供的转发头，按实际连接 IP 重建；管理服务不信任外部 `X-Forwarded-For`。
- `backup.rs`：配置内容版本 2 包含分组，资源和分组在同一事务中替换并重映射关联；兼容版本 1，旧服务恢复为未分组并保留当前分组定义。Argon2id 派生独立备份密钥，AES-GCM 验证完整性。先校验完整资源图和全部 PEM，再生成新资源 ID 与证书目录，最后事务替换配置；不会恢复旧管理员或旧会话。

## 扩展原则

新增模块遵循“配置模型 → 校验 → 持久化迁移 → 独立运行时 → API → UI → 行为测试”。先定义故障与恢复合同，再添加操作入口。不把协议实现在 React 内，不把第三方账户凭据当作前端状态保存。

单实例任务锁不支持水平扩容。若增加多实例，先替换为数据库任务租约和跨实例配置版本广播。若增加多人管理，先把单管理员模型迁移为用户/角色/权限及主体审计，不复用现有单账户假设。

代理的管理面板、目标服务及用户 DNS 使用独立端口。宿主默认绑定私网管理地址；公网暴露管理面板前应配置可信 HTTPS 入口并启用 Secure cookie。实际协议测试与外部服务商测试是不同的验收条件，任何一个不能替代另一个。
